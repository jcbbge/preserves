# AI Assistant Workflows

This document outlines standard workflows for the AI assistant to follow when executing common tasks.

## Feature Planning Workflow

1. **Initialize Planning**
   - Review user story and requirements
   - Identify related components in the system
   - Reference relevant principles

2. **Requirements Analysis**
   - Break down high-level requirements into specific tasks
   - Identify potential edge cases and considerations
   - Map requirements to principles

3. **Technical Approach**
   - Outline components to modify
   - Specify files that will need changes
   - Describe architectural approach

4. **Create Feature Plan**
   - Create structured plan document
   - Include principle adherence section
   - Define success criteria and validation steps

5. **Review and Finalize**
   - Check plan for completeness
   - Verify principle alignment
   - Identify potential risks or challenges

## Implementation Workflow

1. **Prepare Context**
   - Review feature plan
   - Load relevant file content
   - Identify principle considerations

2. **Implementation Planning**
   - Break down implementation into steps
   - Identify potential edge cases
   - Plan tests and validation

3. **Code Generation**
   - Generate code for each component
   - Apply established patterns and conventions
   - Document complex logic

4. **Self-Review**
   - Check for bugs and edge cases
   - Verify adherence to principles
   - Ensure code maintainability

5. **Validation**
   - Validate against requirements
   - Check principle adherence
   - Suggest tests

## Code Review Workflow

1. **Understanding Context**
   - Review the code changes
   - Understand the feature requirements
   - Identify relevant principles

2. **Principle Verification**
   - Check accessibility compliance
   - Verify performance considerations
   - Assess maintainability

3. **Technical Review**
   - Look for bugs and edge cases
   - Check pattern consistency
   - Verify error handling

4. **Feedback Formulation**
   - Provide specific, actionable feedback
   - Reference principles when relevant
   - Balance positive reinforcement and improvement suggestions

5. **Summary and Recommendations**
   - Summarize the review
   - Provide clear next steps
   - Highlight any principle conflicts

## Documentation Workflow

1. **Context Gathering**
   - Identify what was changed
   - Understand the purpose of changes
   - Determine documentation scope

2. **Update System Documentation**
   - Update architecture diagrams
   - Modify component descriptions
   - Document API changes

3. **Update User Documentation**
   - Update user guides
   - Create feature documentation
   - Revise FAQs

4. **Principle Documentation**
   - Document how changes uphold principles
   - Note any principle challenges
   - Update principle implementation examples

5. **Review and Finalize**
   - Check documentation for completeness
   - Verify accuracy
   - Ensure documentation is accessible and clear
