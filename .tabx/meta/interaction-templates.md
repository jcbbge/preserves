# AI Interaction Templates

This document provides standardized templates for common AI interactions to maintain consistency and quality across sessions.

## Mode Switching

### Vision Mode Activation

```
I'd like to switch to Vision Mode to focus on requirements and planning.

Context: [brief description of what we're planning]
Focus: [specific aspect to focus on]
Principles: [relevant principles to emphasize]
```

### Structure Mode Activation

```
I'd like to switch to Structure Mode to design the architecture for this feature.

Context: [brief description of what we're designing]
Components: [components we'll be focusing on]
Principles: [relevant principles to emphasize]
```

### Build Mode Activation

```
I'd like to switch to Build Mode to implement [feature/component].

Context: [brief description of what we're building]
Files: [files to modify]
Boundaries: [what should not be changed]
Principles: [relevant principles to emphasize]
```

## Feature Development Templates

### Feature Planning

```
Let's plan feature: [feature name]

User story: As a [user type], I want to [action] so that [benefit].

Business context:
[Brief description of business need]

Key requirements:
1. [Requirement 1]
2. [Requirement 2]
3. [Requirement 3]

Core principles to emphasize:
- [Principle 1]
- [Principle 2]
```

### Implementation Request

```
Let's implement: [component/feature name]

Feature plan: [link or reference to feature plan]
Files to modify:
- [file path 1]
- [file path 2]

Specific implementation requirements:
1. [Requirement 1]
2. [Requirement 2]

Principles to uphold:
- [Principle 1]
- [Principle 2]
```

### Code Review Request

```
Please review this implementation: [component/feature name]

Feature plan: [link or reference to feature plan]
Files changed:
- [file path 1]
- [file path 2]

Please verify:
1. Adherence to principles, especially [principle(s)]
2. Implementation meets all requirements
3. Code quality and maintainability
4. Potential edge cases or issues
```

## Problem-Solving Templates

### Bug Analysis

```
Let's analyze this bug:

Description: [bug description]
Steps to reproduce:
1. [Step 1]
2. [Step 2]

Expected behavior: [what should happen]
Actual behavior: [what actually happens]

Relevant files:
- [file path 1]
- [file path 2]
```

### Architecture Discussion

```
Let's discuss the architecture for [feature/system]:

Current components:
- [Component 1]: [purpose]
- [Component 2]: [purpose]

Challenges to address:
1. [Challenge 1]
2. [Challenge 2]

Principles to uphold:
- [Principle 1]
- [Principle 2]
```

## Session Management

### Session Start

```
Let's start a new development session.

Focus: [what we'll be working on]
Mode: [Vision/Structure/Build]
Principles: [principles most relevant to this work]
Previous context: [important context from last session]
```

### Session Handoff

```
Let's create a handoff for this session.

Key accomplishments:
1. [Accomplishment 1]
2. [Accomplishment 2]

Important decisions:
1. [Decision 1] because [rationale]
2. [Decision 2] because [rationale]

Next steps:
1. [Next step 1]
2. [Next step 2]

Critical context to preserve:
- [Important context 1]
- [Important context 2]
```
